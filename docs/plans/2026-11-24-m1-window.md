# M1: Kata on the desktop

**Status:** active · **Branch:** `m1-window` off `main` at `e6fd804` · **Started:** 2026-11-24

## Context

BRIEF.md's M1 asks for Kata standing on the floor line in a window that doesn't look like a
window. It should be frameless, see-through, always on top, with no taskbar button, and it
mustn't take keyboard focus. `python -m kata` starts it; the preview moves to
`python -m kata.preview`.

Three things observed on this machine shape the plan:

- **The taskbar auto-hides:** Windows' `SHAppBarMessage` reports autohide=True, bottom edge.
  Qt's `availableGeometry()` is therefore the whole screen (1280x720 in Qt units), so the floor
  is the screen's bottom edge, not the taskbar. BRIEF.md assumed otherwise. CLAUDE.md says to
  update the brief when Qt differs, so step 3 does.
- **`QRect.bottom()` is `y + height - 1`:** it returned 9 for a rect 10 high. The floor row is
  `y + height`. The placement maths never touches `bottom()`.
- **Display scaling is 150%** (`devicePixelRatio` 1.5). At scale 3 each sprite pixel covers 4.5
  real pixels, so the art will look slightly uneven. You judge it by eye; the fix stays in M8.

M1 also builds the `run-kata` skill, so I can measure what I can't see. Your hand checks in step
3 double as its first calibration.

Not in scope: dragging, walking, the tray menu, multi-monitor, crisp scaling (M8).

## Decisions

From the interview (2026-11-24):

1. **Floor:** the bottom of Qt's usable area. On your setup that's the screen's bottom edge,
   and the revealed taskbar covers Kata's feet until it hides again. With a taskbar that's always
   shown, the same code stands Kata on it. No Win32 code in M1.
2. **Scale:** 3, as the brief says (a 144x144 window in Qt units). You judge the unevenness at
   150% during the hand check.
3. **Start spot:** centred on the primary screen.
4. **`run-kata` skill:** built inside M1, as step 4, after the window exists.
5. **Branch:** `m1-window`, as CLAUDE.md names it. It reaches `main` through a pull request
   (CLAUDE.md), proposed after the last step.

Defaults chosen without asking (approved with the plan):

- **Placement maths:** a new no-Qt `geometry.py`, with its own small `Rect`, so the
  `QRect.bottom()` trap can't reach it. `app.py` builds a `Rect` from `x()`, `y()`, `width()`
  and `height()` only. CLAUDE.md's Layout gains the line.
- **Animator API:**
  - `Animator(animations, first)` plays `first` from frame 0.
  - `play(name)` always restarts, even on the same animation; callers play on a change.
  - `advance(dt)` with a negative `dt` raises `ValueError`.
  - It exposes `animation`, `frame` and `finished`.
- **Timer:** a `QTimer` at about 60 Hz (16 ms), fed real elapsed time from `QElapsedTimer`.
  The window repaints only when the frame changes. M2's main tick grows out of this timer.
  *(Changed in step 3 by your choice. The plan first said a timer at the animation's
  `frame_ms`; see Deviations.)*
- **KATA_LOG:** one line per event on standard out, as `kata <seconds since start> <event>
  key=value ...`. M1 logs `placed` with the screen name, `dpr`, the available area, the feet
  point and the window rectangle.
- **Window title:** "Kata". A frameless window doesn't show it, but it lets `run-kata` find the
  window.
- **Click-through:** no mask at first. If your check finds clicks swallowed, step 3 adds
  `setMask(pixmap.mask())` per frame, as BRIEF's watch-out says.
- **Mutation runs:** for the new no-Qt modules in steps 1 and 2 too, although CLAUDE.md only
  requires them from M2. Survivors are reported to you.
- **`run-kata` script:** Python in `tools/inspect_kata.py`, using ctypes and Pillow.
  - **Read-only:** no synthetic clicks or key presses.
  - **DPI first:** it declares itself DPI-aware before reading any coordinate.
  - **Launching:** `--launch` starts Kata with no console window (a console would take focus),
    with `KATA_LOG=1` writing to a log file in a path you pass.
  - **Finding Kata's pixels:** it captures only Kata's square plus 8 px around it, once with
    see-through windows included and once without; the pixels that differ are Kata's. That this
    really isolates Kata is checked in step 4, not assumed.
  - **Where captures go:** the scratchpad, never the repo.
- **Testing the script:** its pure helpers (style-flag decoding, finding the lowest changed
  row) get tests in `tests/test_inspect_kata.py`. `tools/` is checked by mypy but stays outside
  the coverage gate.
